# Railway Deployment Checklist

## 🚀 Quick Deployment Steps

This checklist ensures your Todo App is properly configured for Railway deployment.

### ✅ Pre-Deployment Checklist

- [x] **Railway Configuration Files Created**
  - [x] `railway.json` - Railway build and deploy configuration
  - [x] `nixpacks.toml` - Build environment and dependencies
  - [x] `.railwayignore` - Files to exclude from deployment

- [x] **Docker Configuration Updated**
  - [x] Dockerfile configured for persistent storage at `/data`
  - [x] Singapore timezone (`Asia/Singapore`) set
  - [x] SQLite dependencies included
  - [x] Dynamic PORT configuration

- [x] **Database Path Configuration**
  - [x] `DATABASE_PATH` environment variable support in `lib/db.ts`
  - [x] Automatic fallback to project root if not set
  - [x] Production uses SQLite, development uses mock-db

### 📋 Railway Deployment Steps

#### 1. Push to GitHub

```bash
# Ensure all files are committed
git add .
git commit -m "Prepare for Railway deployment"
git push origin main
```

#### 2. Create Railway Project

1. **Go to [Railway Dashboard](https://railway.app/dashboard)**
2. **Click "New Project"**
3. **Select "Deploy from GitHub repo"**
4. **Choose this repository**
5. **Select branch**: `main` or `solution`

#### 3. Configure Environment Variables

In Railway project > **Variables tab**, add:

**Required:**
```bash
NODE_ENV=production
TZ=Asia/Singapore
DATABASE_PATH=/data/todos.db
```

**Optional (for custom branding):**
```bash
NEXT_PUBLIC_APP_NAME=Todo App
NEXT_PUBLIC_APP_URL=https://your-app.railway.app
```

**WebAuthn Configuration (Required for Authentication):**
```bash
# Will be auto-generated by Railway, but you need these for WebAuthn
RAILWAY_PUBLIC_DOMAIN=your-app.railway.app
NEXT_PUBLIC_RP_ID=your-app.railway.app
NEXT_PUBLIC_RP_NAME=Todo App
NEXT_PUBLIC_ORIGIN=https://your-app.railway.app
```

#### 4. Add Persistent Volume (CRITICAL for Database)

**Why needed:** SQLite database will be lost on redeployments without a volume.

1. **In Railway project, go to your service**
2. **Click "Settings" tab**
3. **Scroll to "Volumes" section**
4. **Click "Add Volume"**
5. **Configure:**
   - **Mount Path:** `/data`
   - **Size:** `1 GB` (can adjust later)
6. **Click "Add"**

#### 5. Deploy Settings Configuration

**In Railway project > Settings:**

1. **Root Directory:** Leave blank (handled by `railway.json`)
2. **Build Command:** Automatic (from `nixpacks.toml`)
3. **Start Command:** Automatic (from `nixpacks.toml`)
4. **Health Check Path:** `/` (optional)

#### 6. Generate Domain

1. **Go to "Settings" > "Networking"**
2. **Click "Generate Domain"** for a Railway subdomain
   - Example: `your-app-production.up.railway.app`
3. **Or add custom domain** (requires DNS configuration)

#### 7. Deploy and Monitor

Railway will automatically:
- ✅ Build the application
- ✅ Install dependencies (including native SQLite)
- ✅ Run build command
- ✅ Start the server
- ✅ Provide deployment logs

**Monitor deployment:**
- **Deployments tab** - See build progress
- **Logs** - View application output
- **Metrics** - Monitor performance

### 🔧 Post-Deployment Configuration

#### WebAuthn Setup (CRITICAL)

After your Railway domain is generated, update environment variables:

```bash
# Replace with your actual Railway domain
NEXT_PUBLIC_RP_ID=your-app-production.up.railway.app
NEXT_PUBLIC_ORIGIN=https://your-app-production.up.railway.app
```

**Redeploy after updating these variables** (Railway will restart automatically)

#### Test WebAuthn Authentication

1. Visit your deployed app
2. Try registering a new user with passkey/biometric
3. Verify login works

**Note:** WebAuthn requires HTTPS. Railway provides this automatically.

### 🔍 Troubleshooting

#### Build Failures

**Error: `better-sqlite3` native binding**
```bash
# Solution: Verify nixpacks.toml includes correct dependencies
nixPkgs = ["nodejs-20_x", "python3", "gcc", "gnumake"]
aptPkgs = ["sqlite3"]
```

**Error: Module not found**
```bash
# Solution: Clear Railway cache and rebuild
# In Railway: Settings > Danger Zone > Clear Cache
```

#### Database Issues

**Database resets on redeploy:**
```bash
# Solution: Ensure volume is mounted at /data
# Check: Settings > Volumes > Mount Path = /data
# Check: Environment variable DATABASE_PATH=/data/todos.db
```

**Cannot write to database:**
```bash
# Solution: Check volume permissions
# Dockerfile already sets: chmod 755 /data
```

#### WebAuthn Failures

**Error: "Origin mismatch"**
```bash
# Solution: Update environment variables with correct Railway domain
NEXT_PUBLIC_RP_ID=your-actual-domain.railway.app
NEXT_PUBLIC_ORIGIN=https://your-actual-domain.railway.app
```

**Error: "RP ID not found"**
```bash
# Solution: Ensure HTTPS is enabled (Railway does this automatically)
# WebAuthn only works over HTTPS
```

### 📊 Monitoring and Logs

**View logs:**
```bash

```

**Common log patterns to watch:**
- `Database initialized at: /data/todos.db` - Database working
- `Server running on port 3000` - App started
- `Error: EACCES` - Permission issues
- `Error: SQLITE_CANTOPEN` - Database path issues

## Quick Reference

### Environment Variables Summary

```bash
# Required
NODE_ENV=production
TZ=Asia/Singapore
DATABASE_PATH=/data/todos.db

# WebAuthn (update with your domain)
NEXT_PUBLIC_RP_ID=your-app.railway.app
NEXT_PUBLIC_ORIGIN=https://your-app.railway.app
NEXT_PUBLIC_RP_NAME=Todo App

# Optional
NEXT_PUBLIC_APP_NAME=Todo App
```

### File Structure for Deployment

```
├── railway.json              # Railway configuration
├── nixpacks.toml            # Build environment
├── .railwayignore           # Excluded files
├── nextjs_server/
│   ├── Dockerfile           # Container config (Railway Persistent storage)
│   ├── package.json         # Dependencies
│   ├── lib/
│   │   ├── db.ts           # Database selector
│   │   ├── sqlite-db.ts    # SQLite implementation
│   │   └── mock-db.ts      # Development fallback
│   └── app/                # Next.js application
```
